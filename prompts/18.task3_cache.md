下一阶段路线图任务 3：热点读 Redis 缓存。
热点识别见 docs/缓存热点数据识别.md，选型记入 docs/重要决策说明.md（#47），
缓存键与失效策略记入 docs/实现说明.md。

请用「手写缓存工具」而非 Spring Cache 注解实现热点读缓存：

1. 基础设施：
   - util/CacheUtil.getOrLoad 两个重载：
     - (key, baseTtl, randomRange, loader, Class<T>)：单实体，
       loader 返回 null 时写空值占位（固定 60s）并抛 404，命中占位直接抛 404
     - (key, baseTtl, randomRange, loader, TypeReference<T>)：集合/分页，不做占位
     - 实际 TTL = baseTtl + random(randomRange) 防雪崩；反序列化失败回源容错
     - JSON 用注入的 Spring ObjectMapper（含 JavaTimeModule）
   - util/CacheKeys：集中管理 key 构造与 TTL/抖动常量
   - util/RedisUtil.deleteByPrefix：用 SCAN 游标分批删除（禁用 KEYS）

2. 缓存点（读方法抽出私有 loader，套 getOrLoad）：
   - 分类树 category:tree（1h）
   - 商店详情 store:detail:{id}（30m）、商店列表 store:list:{page}:{size}（10m）
   - 商品详情 product:detail:{id}（5m，含 stock，靠短 TTL 容忍延迟）
   - 商品评论分页 product:reviews:{id}:{page}:{size}（10m）
   - 店铺/全局订单报表（5m，纯 TTL 不主动清）

3. 写操作主动失效：
   - 增删分类 → 清 category:tree
   - 商店增改 → 清 store:detail:{id} + deleteByPrefix(store:list:)
   - 商品改/删/调库存 → 清 product:detail:{id}
   - 发表评论/回复 → deleteByPrefix(product:reviews:{id}:)

4. 不缓存：优惠券组列表（remainCount 高频变）、商品搜索/店内商品列表
   （多维参数键爆炸）、各用户私有接口。复用现有 StringRedisTemplate，
   不注册 RedisCacheManager。
