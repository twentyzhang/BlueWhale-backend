下一阶段路线图任务 2：并发安全（库存超卖 + 优惠券超发防护）。
背景见 docs/下一阶段路线图.md，选型记入 docs/重要决策说明.md（#45、#46），
表结构变更走 Flyway 新迁移（见 docs/数据库迁移指南.md）。

一、库存超卖（乐观锁，自定义 SQL）：

1. Product 加 @Version version 字段，新增迁移 V2__add_product_version.sql 加列
2. ProductMapper 加两个自定义 @Update：
   - updateStockWithVersion：相对扣减，
     SET stock = stock - #{q}, version = version + 1
     WHERE id=? AND version=? AND stock >= #{q}（含库存下限守卫）
   - updateStockTo：绝对设置（Staff 调库存用），带版本号条件
3. createOrder 扣减、updateStock 调整改为「重读 → 带版本号条件更新 →
   影响 0 行则重试，最多 3 次，仍失败抛『库存更新失败，请重试』」
4. 不注册全局 OptimisticLockerInnerInterceptor（避免影响其他 updateById），
   version 仅由这两个自定义 SQL 推进

二、优惠券超发（Redis 分布式锁 + DB 守卫）：

1. 新增 util/RedisLockUtil：
   - tryLock(key, value, expireSeconds)：SET NX EX
   - unlock(key, value)：Lua 脚本「value 一致才 del」，value 用 UUID
2. claimCoupon 改造：
   - 鉴权后按 coupon_lock:groupId:{id} 加锁（5s 过期），失败抛「系统繁忙」
   - try/finally 确保释放锁；临界区内二次检查 remainCount > 0
   - 扣减改为带守卫的条件更新：remain_count = remain_count - 1
     WHERE id=? AND remain_count > 0，影响 0 行抛「已被抢完」
   - 保留 @Transactional；超发的最终防线是 DB 守卫，锁主要降低无效竞争
3. 不引入 Redisson（临界区短，轻量实现足够）
