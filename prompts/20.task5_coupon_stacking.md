规则与取舍记入 docs/重要决策说明.md（#49），计价流程记入 docs/实现说明.md，
接口变更同步 docs/api-spec.md，表结构变更走 Flyway 迁移（V3）。

已拍板的业务规则：
- 券类型由 2 类拆为 3 类：DISCOUNT（折扣）/ FULL_REDUCTION（满减,有门槛）/
  DIRECT_OFF（直减,无门槛）；同类型至多一张，不同类型可叠加（最多 3 张）
- 满减门槛（minOrderAmount）按「原始订单总额」判定是否达标
- 不同先后会得到不同优惠，后台需返回「最大折扣」方案

请按以下要求实现：

1. 券类型拆分：
   - 迁移 V3__coupon_stacking.sql：把旧 AMOUNT_OFF 按 min_order_amount>0
     拆为 FULL_REDUCTION、否则 DIRECT_OFF
   - 发布券组校验：DISCOUNT 的 value∈(0,1)；FULL_REDUCTION 的 value>0
     且 minOrderAmount>0；DIRECT_OFF 的 value>0 且 minOrderAmount=0

2. 最优计价（纯函数 util/CouponCalculator）：
   - 入参：订单总额 + 已通过资格校验的券（type、value）
   - 穷举所有应用顺序，链式计价（DISCOUNT 乘 value、满减/直减减 value），
     每步四舍五入到分并以 0 兜底，最终实付不低于 0.01
   - 返回折扣最大（实付最小）的方案，含券应用顺序
   - 券数 ≤3、穷举开销可忽略，不必并发；以「实付」为中心反推折扣保证不漏分

3. 下单改造（OrderServiceImpl）：
   - CreateOrderRequest.couponId 改为 couponIds 列表
   - 抽出 resolveCoupons 统一校验：归属/UNUSED/未过期/店铺范围（店铺券仅本店）/
     同类型限一张/满减门槛（按原始总额）；任一失败抛 BusinessException
   - 新增 order_coupon 关联表 + OrderCoupon/OrderCouponMapper 记录一单多券；
     orders.coupon_id 不再写（保留列兼容历史）
   - 取消/退款恢复改为多券：来源 = order_coupon ∪ 历史 coupon_id

4. 试算接口 POST /api/orders/coupon-preview（仅 Customer）：
   - 入参 cartItemIds + couponIds；复用 resolveCoupons 同款校验与计价
   - 只读购物车/商品、不校验库存、不写任何表
   - 返回 totalAmount、discountAmount、payableAmount、appliedCouponIds（最优顺序）
   - 下单时后台重新计算，不信任前端试算结果
