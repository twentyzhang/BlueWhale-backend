> 本路线图规划在此基础上逐步补齐 8 项暂缓功能，**按难度递增 + 价值**排序，不必照需求文档原顺序。

---

## 当前代码现状（影响排序的关键事实）

| 事实 | 影响 |
|---|---|
| 优惠券领取已有原子 `remain_count = remain_count - 1`，但缺 `WHERE remain_count > 0` 下限保护 | 并发下会超发（发成负数） |
| 订单库存扣减是「先读校验再 `updateById` 回写」（`OrderServiceImpl`），无并发保护 | 两单可同时通过校验导致**超卖** |
| Redis 已接入（`RedisUtil`，目前仅用于 refreshToken） | 加缓存成本低 |
| 调度器未启用（无 `@EnableScheduling`） | 定时任务需先开启 |

## 阶段一：低成本 / 高收益（优先）

### 任务 1 — 未支付订单自动取消（定时器）｜难度 ★☆☆☆☆
- **目标**：超时未支付订单自动置为 `CANCELLED` 并恢复库存。
- **方案（已实现）**：`config/SchedulingConfig` 开 `@EnableScheduling`；`job/OrderAutocancelJob` `@Scheduled(fixedDelay=60000)` 每分钟扫描；`OrderMapper.selectExpiredUnpaidOrders` 查 `status=PENDING_PAYMENT` 且 `created_at` 早于 `now - 天数`；逐条 try-catch 调 `OrderService.cancelExpiredUnpaidOrder`（独立事务，恢复库存+优惠券、置 CANCELLED）。天数读配置 `bluewhale.order.auto-cancel-days`（默认 14）。
- **关键文件**：`config/SchedulingConfig`、`job/OrderAutocancelJob`、`OrderMapper`、`OrderService(Impl)`、`application.yml`。
- **依赖**：订单模块（已完成）。自包含、风险低，适合热身。
- **文档义务**：`进度.md`；新调度模块在 `实现说明.md` 记执行流程。

### 任务 2 — 并发安全：库存 & 优惠券超发防护｜难度 ★★☆☆☆ ·【价值最高，修真实 bug】
- **目标**：堵住超卖 / 超发缺口。
- **库存（✅ 已完成，见决策第 45 条）**：`Product` 加 `@Version`（迁移 `V2__add_product_version.sql`）；`ProductMapper` 加 `updateStockWithVersion`（`stock = stock - q, version = version + 1 WHERE version=? AND stock >= q`）与 `updateStockTo`；`createOrder` 扣减与 `updateStock` 调整改为乐观锁 + 重试 3 次。未注册全局 `OptimisticLockerInnerInterceptor`（避免影响其他 `updateById`）。
- **优惠券（✅ 已完成，见决策第 46 条）**：新增 `util/RedisLockUtil`（`SET NX EX` + Lua 解锁）；`claimCoupon` 加组级分布式锁 `coupon_lock:groupId:{id}` + 双重检查 + 扣减守卫 `.gt("remain_count", 0)`。
- **遗留（待办）**：`restoreInventory` 仍为读-改-写（只加库存、不致超卖，但有丢失更新理论窗口），可改为原子 `stock = stock + q`。
- **关键文件**：`ProductMapper`、`Product`、`OrderServiceImpl`、`ProductServiceImpl`、`CouponServiceImpl`（券待办）、迁移脚本。
- **文档义务**：`进度.md`；乐观锁选型 → `重要决策说明.md` #45；实现 → `实现说明.md`；迁移遵循 `数据库迁移指南.md`。

### 任务 3 — 热点读 Redis 缓存｜难度 ★★☆☆☆（✅ 已完成）
- **热点数据识别**：候选对象与定级见 [缓存热点数据识别.md](./缓存热点数据识别.md)。
- **实现（见决策第 47 条 / 实现说明「热点读缓存」）**：手写 `CacheUtil.getOrLoad`（空值占位防穿透 + TTL 抖动防雪崩 + 反序列化容错）+ `CacheKeys` + `RedisUtil.deleteByPrefix(SCAN)`；缓存分类树/商店详情/商店列表/商品详情/商品评论/订单报表，写操作主动失效。商品详情库存取方案 1 短 TTL；优惠券组列表、商品搜索不缓存。
- **方案**：`@EnableCaching` + `RedisCacheManager`（现有 `RedisConfig` 为 `StringRedisTemplate`，需补 JSON 序列化的 CacheManager Bean）；`@Cacheable` 标读，`@CacheEvict` 在商品/分类写操作时失效。
- **关键文件**：`RedisConfig`、`ProductServiceImpl`、`ProductCategoryServiceImpl`、`StoreServiceImpl`。
- **依赖**：Redis（已接）。**注意缓存一致性**：写操作必须配套清缓存。
- **文档义务**：`进度.md`；缓存键设计与失效策略 → `实现说明.md`；引入 Spring Cache 抽象 → `重要决策说明.md`。

- **关键文件**：`pom.xml`、`ReportController` / `AdminController`、`util/ReportExcelExporter`、`util/ExcelDownloadUtil`、`dto/excel/*`。自包含。
- **文档义务**：`进度.md`✅；EasyExcel 选型与新依赖 → `重要决策说明.md`✅；导出流程 → `实现说明.md`✅；接口变更 → `api-spec.md`✅。

### 任务 5 — 多优惠券叠加策略｜难度 ★★★☆☆（✅ 已完成）
- **目标**：下单支持多张券组合，定义叠加规则与计算顺序。
- **已拍板规则**：① 券类型由 2 类拆为 3 类 **DISCOUNT(折扣)/FULL_REDUCTION(满减)/DIRECT_OFF(直减)**，同类型至多一张、不同类型无限叠加；② 满减门槛按**原始订单总额**判定；③ 不同先后产生不同优惠，后台求**最大折扣**（已证明「先乘性折扣后加性减免」最优，实现用穷举保证正确，券数 ≤3 开销可忽略、无需并发）；④ 新增**试算接口**供前端下单前预览。
- **实现（见决策第 49 条 / 实现说明「多优惠券叠加」）**：`util/CouponCalculator`（纯函数，穷举排列取最优）；`OrderServiceImpl.resolveCoupons` 统一校验+计价，`createOrder` 与新 `previewCoupon` 共用；`CreateOrderRequest` 改收 `couponIds`；新增 `order_coupon` 关联表（迁移 V3）+ `OrderCoupon`/`OrderCouponMapper`；取消/退款恢复改为多券；`POST /api/orders/coupon-preview` 试算。
- **关键文件**：`util/CouponCalculator`、`OrderServiceImpl`、`CreateOrderRequest`、`CouponPreview{Request,Response}`、`OrderCoupon(Mapper)`、`CreateCouponGroupRequest`、`CouponGroupServiceImpl`、`V3__coupon_stacking.sql`。
- **文档义务**：叠加规则 → `重要决策说明.md` #49 ✅；计价流程 → `实现说明.md` ✅；接口变更 → `api-spec.md` ✅；迁移 → `数据库迁移指南.md` ✅。
