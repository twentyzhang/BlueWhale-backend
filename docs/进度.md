## 建议实现顺序

```
1. JWT 基础设施（依赖 → 工具类 → Filter → SecurityConfig 接入）
2. 用户模块（注册 + 登录，产出可用 Token，其余模块都需要鉴权）
3. 商品浏览（分类树、商店列表、商品列表/详情/搜索，无需登录，便于早期联调）
4. 购物车模块
5. 收货地址模块
6. 商店管理 + 商品管理（Staff/Admin 操作）
7. 订单模块（依赖购物车、地址、商品库存）
8. 优惠券模块（领取 + 下单时核销，依赖订单模块）
9. 评论模块（依赖订单完成状态）
10. 报表模块（依赖订单数据）
```

## 已知技术债

| 项目 | 状态 | 说明 |
| ---- | ---- | ---- |
| `ApiResponse<T>` 残留 | 已清除 | Controller 已全面切换到 `Result<T>`，旧类已删除 |
| `getCurrentUserId()` 返回 null | 已解决 | JWT Filter 接入后统一从 SecurityContext（`AuthUtil`）读取 |
| JWT 依赖缺失 | 已解决 | `jjwt` 0.12.6（api/impl/jackson）已引入 |
| 未登录返回 403 而非 401 | 待定 | Spring Security 无 `AuthenticationEntryPoint`，未登录访问受保护接口返回 403（语义上应为 401）。不影响功能，前端已按「401/403 均触发刷新/重登」处理 |
| 恶意请求体返回 500 | 待定 | 非法 JSON / 非 UTF-8 请求体经 `HttpMessageNotReadableException` 落入通用 500 分支（语义上应为 400）。如需可在 `GlobalExceptionHandler` 增补处理 |
| 库存超卖 | 已解决 | `createOrder` 扣减、`updateStock` 调整均改为乐观锁（`@Version` + 自定义 SQL `stock >= quantity` 原子条件 + 重试 3 次），见决策第 45 条、迁移 `V2__add_product_version.sql` |
| 优惠券超发 | 已解决 | `claimCoupon` 加 Redis 分布式锁（组级互斥）+ 双重检查 + 扣减守卫 `remain_count > 0`，见决策第 46 条、`util/RedisLockUtil` |
