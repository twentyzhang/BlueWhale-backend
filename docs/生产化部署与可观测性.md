# 生产化部署与可观测性

本文说明如何用 Docker Compose 启动 BlueWhale 后端准生产演示栈，并验证健康检查、Prometheus 指标、Grafana 看板和 requestId 日志。

## 前置要求

- Docker Desktop 或 Docker Engine + Docker Compose v2
- 可选：通义 DashScope `DASHSCOPE_API_KEY`，用于真实 AI embedding / qwen 联调

## 启动步骤

```bash
copy .env.example .env
docker compose --env-file .env up -d --build
```

首次启动会拉取 MySQL、Redis、Qdrant、Prometheus、Grafana 镜像，并构建 BlueWhale app 镜像，耗时较长是正常现象。

## 访问地址

| 服务 | 地址 |
|---|---|
| BlueWhale app | http://localhost:8080 |
| Health | http://localhost:8080/actuator/health |
| Qdrant Dashboard | http://localhost:6333/dashboard |
| Prometheus | http://localhost:9090 |
| Grafana | http://localhost:3000 |

Grafana 默认账号密码来自 `.env`：`GRAFANA_ADMIN_USER` / `GRAFANA_ADMIN_PASSWORD`。

## 验证 Prometheus 抓取

1. 打开 http://localhost:9090/targets
2. 确认 `bluewhale-app` 为 `UP`
3. 查询 `process_uptime_seconds{job="bluewhale-app"}`

Prometheus 通过 `X-Metrics-Token` 抓取 `/actuator/prometheus`。该值必须与 `.env` 中的 `MANAGEMENT_METRICS_TOKEN` 一致；如果修改真实环境 token，也要同步修改 `deploy/prometheus/prometheus.yml`。

## 验证 requestId

```bash
curl -i http://localhost:8080/actuator/health
curl -i -H "X-Request-Id: demo-request-1" http://localhost:8080/actuator/health
docker logs bluewhale-app --tail=100
```

响应头应包含 `X-Request-Id`，应用日志中应出现相同 requestId。

## 常见问题

| 问题 | 处理 |
|---|---|
| 端口占用 | 修改 `.env` 中的 `APP_PORT`、`MYSQL_PORT`、`REDIS_PORT`、`QDRANT_REST_PORT`、`PROMETHEUS_PORT`、`GRAFANA_PORT` |
| MySQL 首次启动慢 | 等待 healthcheck 变为 healthy；查看 `docker logs bluewhale-mysql` |
| Prometheus target 401/403 | 确认 `deploy/prometheus/prometheus.yml` 中的 `X-Metrics-Token` 与 `.env` 的 `MANAGEMENT_METRICS_TOKEN` 一致 |
| AI 搜索降级为关键词搜索 | 确认 `DASHSCOPE_API_KEY` 已配置；Qdrant 正常不代表 DashScope 一定可用 |
| Qdrant dashboard 无 collection | 调用 Admin reindex 后等待 outbox relay 消费 |

## 停止与清理

```bash
docker compose --env-file .env down
docker compose --env-file .env down -v
```

`down -v` 会删除 MySQL、Redis、Qdrant、Prometheus、Grafana 的命名卷，请谨慎使用。
