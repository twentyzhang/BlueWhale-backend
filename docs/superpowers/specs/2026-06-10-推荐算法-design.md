## 1. 目标与范围

基于订单历史的 **item-based 协同过滤**，提供两个推荐位：

- **接口 A — 商品相关推荐**：给定一个商品，推相似商品（"买了又买 / 相关推荐"）。
- **接口 B — 个性化猜你喜欢**：给定一个用户，基于其购买历史推个性化商品。

A 是核心引擎（物品两两相似度），B 在 A 之上做用户级聚合。**先实现 A，再实现 B。**

**v1 不做**（YAGNI）：购物篮搭配推荐（多商品入参）、矩阵分解 / 深度模型、实时在线计算、基于浏览/评分的信号。

## 2. 算法设计

### 2.1 相似度：加权余弦

- **共现口径**：**同一用户跨订单**——同一用户在任意时间买过 A 也买过 B，即记一次共现。（非"同一购物篮"。）
- **相似度公式**：加权余弦

  ```
  sim(A,B) = Σ_u ( w(u,A) · w(u,B) ) / ( √Σ_u w(u,A)² · √Σ_u w(u,B)² )
  ```

  其中 `w(u,P)` = 用户 u 对商品 P 的兴趣权重（见 2.2）。`Σ_u` 仅对同时与 A、B 有交互的用户求分子。

- 每个商品取 **Top-N 相似商品**（N 默认 50，存储上限；接口按 `limit` 截取）。
- 排除自身（A 不和自己算相似）。

### 2.2 状态加权

订单全部下单状态均纳入，但按状态赋兴趣权重（"下单即兴趣，但满意度有别"）：

| `orders.status` | 含义 | 权重 |
|---|---|---|
| `COMPLETED` / `SHIPPED` / `PAID` | 真实成交 | 1.0 |
| `PENDING_PAYMENT` | 下单未付（含意图未承诺） | 0.5 |
| `CANCELLED` | 下单后取消 / 自动弃单 | 0.3 |

> 实现前须到 `entity/Order` 与 `OrderServiceImpl` 核对确切状态枚举值（确认是否存在独立的退款状态，如有则按弱信号或排除处理）。权重值作为可调常量集中定义。

**同一用户对同一商品多次购买的权重合并规则**：**取最大值**（`w(u,P) = max(各订单状态权重)`），不累加。理由：累加会让刷单 / 重复下单异常放大权重，取最大更稳健，且语义清晰（"该用户对该商品的最强兴趣信号"）。

### 2.3 接口 B 的聚合逻辑

```
取用户所有"有效订单"买过的商品集合 H（带各自权重）
for 每个 h ∈ H:
    取 h 的相似商品集 S_h（来自 product_similarity）
    for 每个 (s, score) ∈ S_h:
        candidate[s] += w(u,h) · score      // 按用户对源商品的兴趣加权累加
candidate 去掉 H 中已有的商品（排除已购）
按累加分降序取 Top-limit
不足 limit → 用全站热销补足
```

## 3. 架构：离线预计算 + 线上查表 + 多级缓存

### 3.1 离线预计算

相似度是慢变量，放离线批处理，线上只查表。

- **定时**：`@Scheduled(cron = "0 0 3 * * ?")` 每天凌晨 3:00。复用任务 1 已启用的 `@EnableScheduling`。
- **手动触发**：Admin 接口 `POST /api/admin/recommendations/rebuild` 立即重算（本地调试 / 演示用）。
- **任务职责**（`RecommendationRebuildJob` → `RecommendationService.rebuildAll()`）：
  1. 扫订单（join `order_item`）算每个用户对每个商品的权重；
  2. 计算商品两两加权余弦 → 每商品 Top-N → 写 `product_similarity` 表 + 刷 Redis ZSET；
  3. 算热销榜（全站 + 每类目，按 `SUM(quantity)`）→ 写 Redis（+ 表备份，见 4.2）。

### 3.2 多级缓存：真相来源 vs 缓存

- **真相来源 = MySQL `product_similarity` 表**（关机不丢，重启即用）。
- **Redis ZSET = 热读缓存**，read-through：先查 ZSET，未命中（重启 / 缓存被清）→ 回 MySQL 表 → 回填 ZSET → 返回。
- 数据量小时 MySQL 表配索引已毫秒级；Redis 层为多级缓存实践 + 应对未来热点，可平滑降级（ZSET 失效不影响正确性）。

## 4. 数据模型（Flyway `V5__recommendation.sql`）

### 4.1 相似度表

```sql
CREATE TABLE product_similarity (
    id                  BIGINT      NOT NULL AUTO_INCREMENT,
    product_id          BIGINT      NOT NULL,
    similar_product_id  BIGINT      NOT NULL,
    score               DECIMAL(10,8) NOT NULL,   -- 加权余弦，0~1
    created_at          DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_pair (product_id, similar_product_id),
    KEY idx_product_score (product_id, score)      -- 查 Top-N
);
```

重建时按 `product_id` 整体替换（先删该商品旧行再插新行，或 truncate 全表重建——v1 数据量小，倾向**全表重建**，事务内 `DELETE` + 批量 `INSERT`）。

### 4.2 热销榜

热销榜数据小、易重算，**优先存 Redis**：

- `rec:hot:global`（ZSET，成员=productId，score=成交件数）
- `rec:hot:cat:{categoryId}`（ZSET，每类目一份）

为防关机丢失同样落一份 MySQL 备份表 `product_hot_rank(scope, category_id, product_id, sales, ...)`，read-through 重建。（若实现时认为热销榜每次重算成本极低，可省去备份表、重启后由首个请求或下次 job 重算——实现时二选一，倾向保留备份表以与相似度表保持一致的多级缓存模式。）

### 4.3 Redis 键

| 键 | 类型 | 内容 |
|---|---|---|
| `rec:sim:{productId}` | ZSET | 相似商品（成员=similarProductId，score=相似度） |
| `rec:hot:global` | ZSET | 全站热销（成员=productId，score=成交件数） |
| `rec:hot:cat:{categoryId}` | ZSET | 类目热销 |

## 5. 接口

| 接口 | 方法 / 路径 | 鉴权 | 行为 |
|---|---|---|---|
| A 相关推荐 | `GET /api/products/{productId}/recommendations?limit=10` | 开放 | 查 `rec:sim:{id}`（未命中回表）；不足 → 同类目热销 → 全站热销补位；**不排除已购** |
| B 个性化 | `GET /api/recommendations?limit=10` | 需登录 | 聚合用户已购商品的相似集（见 2.3），加权去重，**排除已购**；新用户 / 聚合不足 → 全站热销 |
| 重建 | `POST /api/admin/recommendations/rebuild` | Admin | 同步或异步触发 `rebuildAll()`，返回耗时 / 条目数 |

- **鉴权**：A 放进 `SecurityConfig` 开放 GET 白名单（与商品浏览同列）；B 需登录（userId 从 JWT 取）；Admin 接口限 ADMIN 角色。
- **返回**：复用现有商品摘要 DTO（与商品列表 / 搜索接口一致：id、name、price、imageUrl 等），保持前端统一。
- `limit` 默认 10，设上限（如 ≤50）防滥用。

## 6. 冷启动兜底

统一分层，逐层补足到 limit，保证推荐位不空白：

```
CF 结果 → 同类目热销（product.categoryId 相同）→ 全站热销
```

| 场景 | 兜底 |
|---|---|
| A：新商品 / 相似不足 | 同类目热销补位 |
| A：商品无类目 | 全站热销 |
| B：新用户 / 聚合不足 | 全站热销 |

补位时去重（不重复已在结果中的商品）。
