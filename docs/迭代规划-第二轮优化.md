## 任务 A — 健壮性 / HTTP 语义｜★☆☆☆☆

- **目标**：补齐两处语义错误 + 一处并发收尾。
- **A1 未登录返回 401**：新增 `AuthenticationEntryPoint`（返回 `Result` 包装的 401），`SecurityConfig.exceptionHandling()` 注册；同时配 `AccessDeniedHandler` 让 403 也走 `Result` 结构。
- **A2 非法请求体返回 400**：`GlobalExceptionHandler` 增 `@ExceptionHandler(HttpMessageNotReadableException.class)` → 400，替代落入通用 500。
- **A3 `restoreInventory` 原子化**：`ProductMapper` 增 `increaseStock(productId, qty)`（`stock = stock + #{qty}` 原子），`OrderServiceImpl` 取消/退款恢复库存改用它，消除读-改-写丢失更新窗口。
- **关键文件**：`config/SecurityConfig`、新建 `config/RestAuthenticationEntryPoint` / `RestAccessDeniedHandler`、`exception/GlobalExceptionHandler`、`mapper/ProductMapper`、`service/impl/OrderServiceImpl`。
- **文档义务**：`进度.md`；语义修正 → `实现说明.md`；技术债表标记已解决；前端 401/403 行为 → `frontend-handoff.md`。

## 任务 B — 客服收尾｜★★★☆☆

- **目标**：补齐任务7 决策 #51 记录的三项遗留。
- **B1 接待会话超时自动释放**：新 `@Scheduled` 任务，扫描 `assignee_staff_id` 非空但该客服已离线（不在 `cs:online:store:{id}`）且超过阈值的会话，自动 release 并广播 `RELEASED`。需引入「接待时间 / 客服掉线时间」判定（设计时定：新增 `assigned_at` 列或借 `last_message_at`）。
- **B2 STOMP ERROR 帧**：注册 `StompSubProtocolErrorHandler`，CONNECT/SEND 鉴权失败时回结构化 ERROR 帧，提升前端可诊断性。
- **B3 在线状态心跳 TTL 兜底**：STOMP 心跳配置 + 在线集成员带 TTL（或定期对账），清理进程异常退出遗留的「假在线」脏数据。
- **关键文件**：新建 `job/ChatSessionTimeoutJob`、`config/WebSocketConfig`（心跳 + ErrorHandler）、新建 `interceptor` 或 `handler` 错误处理、`listener/WebSocketPresenceListener`、可能的迁移（assigned_at 列）。
- **依赖**：任务7。**实现前 brainstorm**（超时阈值、掉线时间来源、心跳策略需定）。
- **文档义务**：`进度.md`、`实现说明.md`、`重要决策说明.md`（更新 #51 遗留项状态）、`frontend-handoff.md`（ERROR 帧、自动释放行为）、迁移（如加列）。

## 任务 D — 模拟支付网关｜★★★★☆ ·【本轮压轴】

- **目标**：用「可插拔的模拟支付网关」复刻真实第三方支付的**异步回路**，不接真支付宝、不碰内网穿透；接口留好，未来可平滑替换为真沙箱。
- **方案**：
  - 定义 `PaymentGateway` 接口（`createPayment` / `verifyCallback` / `queryStatus`），实现 `MockPaymentGateway`（适配器模式 / 依赖倒置）。
  - **支付流水表**（迁移 V6 `payment`）：`order_id, trade_no, amount, status(PENDING/SUCCESS/FAILED), ...`，订单 ≠ 支付流水。
  - 改造支付流程为异步：`POST /api/orders/{id}/pay` 不再同步置 PAID，而是建支付流水(PENDING) + 返回模拟「支付链接 + tradeNo」。
  - 模拟收银台动作 → 触发**异步回调**至 `POST /api/payments/notify`，带 **HMAC 签名**（模拟 RSA 验签）。
  - 回调处理：**验签 → 幂等检查（tradeNo 是否已处理）→ 订单 PENDING_PAYMENT→PAID + 流水 SUCCESS**，全程幂等（notify 可重复）。
  - **主动查询** `GET /api/payments/{tradeNo}`（模拟对账兜底），以及支付超时/失败路径。
- **核心可学点**：异步支付状态机、webhook 验签、幂等回调、支付流水建模、支付提供方抽象——真接支付宝时业务回路几乎不用改，只加 `AlipayPaymentGateway` 实现。
- **关键文件**：新建 `service/PaymentGateway` + `impl/MockPaymentGateway`、`service/PaymentService(Impl)`、`controller/PaymentController` + 模拟收银台 `controller/MockCashierController`、`entity/Payment` + `mapper/PaymentMapper`、`V6__payment.sql`、改 `OrderServiceImpl.payOrder`。
- **依赖**：订单模块。**实现前 brainstorm → spec → plan**（流水状态机、幂等键、异步触发方式、失败/超时路径需定稿）。
- **文档义务**：全套——`进度.md`、`实现说明.md`、`重要决策说明.md`（支付网关抽象 + 异步回路选型）、`api-spec.md`、`frontend-handoff.md`（**破坏性变更：支付由同步改异步**）、`数据库迁移指南.md`（V6）。

## 任务 E — 认证增强｜★★★☆☆

- **目标**：在已有双令牌基础上增强安全性（参考 #1）。
- **E1 即时令牌撤销**：新增退出登录接口，使当前 access/refresh 立即失效；改密时同样失效旧令牌。实现可用 access token 的 `jti` 黑名单（Redis，TTL=token 剩余有效期）或用户级 token 版本号。
- **E2 缩短 access token**：24h → 15min（配置），配合 refresh 轮换降低暴露窗口。
- **E3 RS256（可选）**：HS256 对称 → RS256 非对称（私钥签、公钥验），更贴近生产；列为可选，按兴趣做。
- **关键文件**：`util/JwtUtil`、`filter/JwtAuthenticationFilter`（校验黑名单）、`controller/AuthController`（logout）、`service/impl/UserServiceImpl`（改密失效）、`util/RedisUtil`、`application.yml`（有效期 / 密钥）。
- **依赖**：用户模块。**改密失效与现有 refresh 轮换的交互需理清**（建议实现前简短 brainstorm）。
- **文档义务**：`进度.md`、`实现说明.md`、`重要决策说明.md`（撤销机制 + RS256 选型）、`api-spec.md`（logout）、`frontend-handoff.md`（短 access + 退出登录 + 撤销语义）。

## 任务 F — 缓存增强（single-flight + Caffeine L1）｜★★★☆☆

- **目标**：补 `CacheUtil` 的并发回源缺口 + 升级为三级缓存（参考 #6）。
- **F1 single-flight 单飞锁**：`CacheUtil.getOrLoad` 缓存未命中时，同一 key 的并发请求只放一个去回源、其余等待复用结果，防缓存击穿（缓存雪崩/穿透已有保护，**击穿是当前缺口**）。单机用本地按 key 锁（如 `ConcurrentHashMap` 占位 / Guava Striped）；如需跨实例可复用 `RedisLockUtil`。
- **F2 Caffeine 本地 L1**：引入 Caffeine 依赖，热点读路径加 L1（Caffeine）→ L2（Redis）→ DB 三级；选少量真热点（分类树、商店详情、商品详情）接入，注意 L1 失效策略（写操作或短 TTL）。
- **关键文件**：`pom.xml`（Caffeine）、`util/CacheUtil`（single-flight）、新建 `config/CaffeineConfig` 或 `util/LocalCache`、热点读 ServiceImpl 接入点。
- **依赖**：任务3 缓存。方案明确，可直接计划。
- **文档义务**：`进度.md`、`实现说明.md`（三级缓存读写 + single-flight）、`重要决策说明.md`（引入 Caffeine + 单飞锁选型）。
