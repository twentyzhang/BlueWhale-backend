# 南鲸商城 BlueWhale — 项目说明

> 一个专注国货品牌的在线购物平台后端，覆盖商品浏览、购物车、下单、模拟支付、库存管理、评论、优惠券与数据报表的全流程电商服务，并叠加了**实时客服、推荐算法与三个 AI 应用（语义搜索 + RAG 导购问答 + 多轮导购 Agent）**。
>
> 基于 Spring Boot 3 + MyBatis Plus + Spring Security(JWT) + Redis 构建，采用分层架构与无状态鉴权。全部业务功能已完成，并扩展了**并发安全（乐观锁 + 分布式锁）、多级热点读缓存、报表 Excel 导出、多优惠券叠加、STOMP 实时客服、item-based 推荐算法、可插拔异步模拟支付网关、AI 语义搜索（向量检索）、RAG 导购问答（SSE 流式生成）与 AI 导购 Agent（多轮工具调用 + 生产化护栏）**等进阶能力，配有 **353 个测试**（纯 Mockito 单测 + 端到端集成测试，全部通过）。

## 一、项目简介

南鲸商城（BlueWhale）是一个面向**消费者 / 门店店员 / 平台管理员**三类角色的多商店电商平台后端。它以 RESTful API 形式对外提供服务，前后端分离，前端可凭本仓库的 [前端对接文档](./frontend-handoff.md) 直接对接。

| 指标             | 数值                                                                                                                       |

| REST 接口        | 68 个（另有 2 个 STOMP 消息端点 + 2 个 SSE 流式端点）                                                                       |
| 数据表           | 18 张（Agent 只读既有表，无新增迁移）                                                                                        |
| 主代码 Java 文件 | 211 个（含 22 Controller / 21 Service 接口 + 20 实现 / 18 Entity / 18 Mapper / 69 DTO，另有 job / listener / interceptor / filter） |
| 测试             | 353 个（41+ 个测试类，纯 Mockito 单测 + WebSocket / 支付 / 语义搜索 / Agent 端到端集成测试，全部通过）                     |

## 三、角色与权限

| 角色          | 标识         | 能力                                                                                             |
| ------------- | ------------ | ------------------------------------------------------------------------------------------------ |
| 游客 Guest    | （未登录）   | 浏览商店 / 商品 / 分类 / 评论 / 可领券列表 / 商品相关推荐 / **AI 语义搜索 / AI 导购问答**；导购 Agent 需登录 |
| 顾客 Customer | `CUSTOMER` | 购物车、下单、支付、确认收货、取消、退款、评论、领券用券、地址管理、个性化推荐、向店铺客服发消息 |
| 店员 Staff    | `STAFF`    | 管理**本店**商品 / 库存 / 订单（发货）/ 店铺优惠券，查看本店报表，接待本店客服会话         |
| 管理员 Admin  | `ADMIN`    | 创建/维护商店、发布全局优惠券、删除分类、查看全局报表、手动触发推荐重建                          |

**鉴权策略**：无状态 JWT。登录签发短 accessToken（15min）与 refreshToken（7d，存 Redis，刷新即轮换）。请求头 `Authorization: Bearer <token>`，由 `JwtAuthenticationFilter` 解析为 `AuthUser` 写入 `SecurityContext`；具体的角色与归属校验由 Service 层的 `AuthUtil` 完成（路由放行与业务鉴权分离）。令牌支持**即时撤销**：登出 / 改密后旧 accessToken 立即失效（令牌版本号机制，决策 #54）。

## 五、系统架构

经典分层 + 无状态安全过滤链：

```
                    HTTP 请求
                       │
            ┌──────────▼───────────┐
            │ JwtAuthenticationFilter│  解析 Bearer Token → AuthUser → SecurityContext
            └──────────┬───────────┘
                       │
            ┌──────────▼───────────┐
            │  SecurityFilterChain  │  /api/auth/** 与商品浏览类 GET 放行，其余需认证
            └──────────┬───────────┘
                       │
   Controller (@RestController)        路由、参数校验(@Valid)、统一包装 Result<T>
        │
   Service / ServiceImpl               业务逻辑 + AuthUtil 角色/归属鉴权 + @Transactional
        │
   Mapper (MyBatis Plus BaseMapper)    CRUD / 分页 / 逻辑删除；复杂聚合用自定义 SQL
        │
   MySQL  ＋  Redis(令牌 / 缓存 / 在线状态 / 分布式锁 / 推荐 ZSET)  ＋  Qdrant(向量库)
        │
   外部：通义 DashScope（embedding / qwen，经 RestClient REST 直调）
```

**另有多条非传统请求-响应路径**：

- **STOMP over WebSocket**（`/ws` 端点）：CONNECT 帧 JWT 鉴权（`StompAuthChannelInterceptor`）→ `@MessageMapping` 路由消息 → 内存 Broker 广播 / 点对点投递；在线状态由 `WebSocketPresenceListener` 维护到 Redis。
- **SSE 流式**（`GET /api/products/qa`、`GET /api/assistant/chat`）：`SseEmitter` 主线程秒返回不阻塞，后台线程池流式生成；RAG 事件序列 `products → answer* → done/error`；Agent 序列 `step → tool → products → answer* → done/error`。
- **Transactional Outbox 中继**：商品写与 `index_outbox` 事件同事务提交，`OutboxRelayJob` 每 5s 轮询 PENDING → embed → 同步 Qdrant，保证「商品变更 → 向量索引」可靠最终一致。
- **定时任务**（`@EnableScheduling`）：未支付订单自动取消（每分钟）、推荐相似度离线重建（每日 03:00）、客服接待超时释放（每 5 分钟）、支付回调异步触发（`TaskScheduler` 延迟 ~1.5s）。

**横切设施**：

- `Result<T>` 统一响应封装（code/message/data）。
- `GlobalExceptionHandler`（`@RestControllerAdvice`）：校验 / 非法请求体→400、`BusinessException`→自定义码、未认证→401、无权限→403、其余→500。
- `MybatisPlusConfig` 分页拦截器；逻辑删除（`deleted` 字段）全局生效。
- `CacheUtil`/`RedisLockUtil`：多级热点读缓存（Caffeine L1 + Redis L2 + single-flight 防击穿、空值占位防穿透、TTL 抖动防雪崩、SCAN 失效）与分布式锁（`SET NX EX` + Lua 解锁）。
- Flyway 数据库迁移：`V1~V7` 版本化迁移 + `R__` 种子，启动自动执行。

## 七、核心实现要点

> 详细算法与边界处理见 [实现说明.md](./实现说明.md)。

- **下单两阶段设计**：先只读全量校验（购物车归属、地址、库存、优惠券状态与过期、金额计算），全部通过后再统一写库（扣库存→建订单→建条目快照→核销券→清购物车），整体 `@Transactional` 保证原子性。
- **金额计算**：`DISCOUNT` 按折扣率、`FULL_REDUCTION` 按满减门槛、`DIRECT_OFF` 无门槛直减，`payableAmount = max(0.01, total − discount)`，统一 2 位 HALF_UP。
- **分类树构建**：一次全量查询 + 两次线性遍历（Map 建索引 → 按 parentId 挂载），O(n) 组装嵌套树，避免递归查库。
- **避免 N+1**：列表场景统一「二次批量查询」（收集本页外键 → `selectBatchIds` 一次查 → Map 回填），如商品的 categoryName、评论的昵称。
- **快照机制**：订单条目与收货地址在下单时落库快照，商品改价/改名、用户改址均不影响历史订单展示。
- **Token 刷新与轮换**：`POST /api/auth/refresh` 校验 Redis 中 refreshToken 后签发新 accessToken，并**轮换 refreshToken**（旧值立即失效、重置 7 天），降低重放风险。
- **报表聚合**：`GROUP BY/SUM` 等 MyBatis Plus QueryWrapper 不支持的聚合改用自定义 SQL；门店与全局报表共用聚合逻辑，靠 `storeId IS NULL` 分支切换范围。
- **并发安全**：库存扣减用乐观锁（`@Version` + `stock >= q` 原子条件 + 重试 3 次）防超卖；优惠券领取用 Redis 分布式锁 + `remain_count > 0` 守卫防超发。
- **热点读缓存**：分类树 / 商店 / 商品详情 / 评论 / 报表等手写 `getOrLoad` 缓存（空值占位防穿透、TTL 抖动防雪崩），写操作主动 `SCAN` 失效。
- **多优惠券叠加**：券分 折扣 / 满减 / 直减 三类，同类至多一张、跨类叠加；后台穷举最优计价顺序，并提供下单前试算接口。
- **实时客服**：STOMP 消息按会话归属路由（未接入→广播店铺主题，已接入→点对点）；STOMP 推送延迟到事务提交后，消除 REST-then-WS 会话不可见竞态。
- **推荐算法**：加权余弦相似度（状态加权取最大），离线预计算写 `product_similarity` 表（真相来源）+ Redis ZSET 热读缓存（read-through），冷启动按「同类目热销→全站热销」兜底。
- **模拟支付（异步回路）**：`PaymentGateway` 抽象（`MockPaymentGateway` 实现 HMAC-SHA256 验签），复刻第三方支付：发起建流水 → 收银台立即返回 → `TaskScheduler` 延迟异步回调 → 前端轮询查单。幂等并发安全靠流水状态守卫（`WHERE status='PENDING'`）+ 订单 `markPaid`（`WHERE status='PENDING_PAYMENT'`）双原子推进；回调路径不读 SecurityContext，鉴权置于 REST 入口。
- **AI 语义搜索（方案 C outbox）**：商品写与 `index_outbox` 事件同事务原子提交，中继异步 embed 并同步 Qdrant；以 `productId` 作 point id 天然幂等、至少一次投递、失败重试超限置 FAILED；分类/价格作 Qdrant payload 过滤下推、命中按 score 重排回表；embedding/Qdrant 不可用优雅降级关键词搜索。
- **RAG 导购问答**：检索复用语义搜索（一份 `ProductListItemResponse` 既当商品卡又当 LLM 上下文）→ `RagPromptBuilder` 构造严格 grounding 的 system + 候选上下文 user → `QwenChatClient` 流式生成，经 `SseEmitter` 推 `products→answer*→done`；检索为空短路不调 qwen；`ChatCompletionClient` 抽象，切 DeepSeek 仅改配置。
- **AI 导购 Agent（多轮工具调用）**：手写 Agent 循环（非 Spring AI 框架）——非流式工具轮（LLM → tool_calls → `ToolRegistry.execute` → 结果回填）最多 `maxRounds=5` 次，最后一轮 `streamFinal` 流式生成最终回答；6 个工具（4 个公开只读 + 2 个个人数据，个人数据工具强制 `ctx.userId()` 防越权）；客户端断开用每请求 `AtomicBoolean` 短路剩余轮次。生产化护栏：Resilience4j CB+重试（embedding 失败降级关键词搜索、LLM CB 快速失败）、Redis Lua 固定窗口限流（20/60s，`RateLimitInterceptor`）、Micrometer 指标（工具调用/Agent 轮数/限流拒绝）+ Actuator Prometheus 端点（`hasAuthority("ADMIN")` 鉴权，注意裸串无 ROLE_ 前缀）。

## 八、技术亮点

1. **三个 AI 应用落地（最新亮点）**：
   - **语义搜索**用 **transactional outbox** 可靠同步「商品变更 → 向量索引」，Qdrant 向量库 + 通义 `text-embedding-v3`，过滤下推 + score 重排，AI 基础设施不可用时**透明降级**关键词搜索。真实联调验证纯语义召回（如「做饭用的调味料」→橄榄油/酱油，查询词无任何字面匹配）。
   - **RAG 导购问答**在检索基座上叠加 `qwen-plus` **SSE 流式生成**，严格 grounding（只能从候选推荐、不编造）+ 空结果短路，`ChatCompletionClient` 抽象可一键切换 DeepSeek。**全程零新增 Maven 依赖**（`RestClient` + `SseEmitter` 直调 REST）、复用同一 DashScope key。
   - **AI 导购 Agent（最新）**：手写多轮 Agent 循环（非框架），6 个工具（含越权防护的个人数据工具），SSE 推 `step/tool/products/answer/done/error` 全链路事件；生产化护栏三件套——Resilience4j 熔断/重试（embedding 失败透明降级、LLM 快速失败）+ Redis Lua 固定窗口限流 + Micrometer/Prometheus 监控指标，可用性与可观测性兼备。
2. **可插拔异步支付网关**：`PaymentGateway` 抽象复刻第三方支付异步回路（发起→收银台→延迟异步回调→查单轮询），HMAC 验签 + 流水/订单双原子状态守卫保证幂等与并发安全，未来可平滑替换支付宝实现，已配端到端集成测试。
3. **并发安全实战**：针对真实的超卖 / 超发缺口，分别用**乐观锁**（库存：`@Version` + `stock >= q` 原子条件 + 重试）与 **Redis 分布式锁**（优惠券：组级互斥 + 双检 + 守卫）封堵，附迁移与决策留痕。
4. **多级缓存设计**：**Caffeine L1 + Redis L2 + single-flight** 三级缓存（防穿透 / 防雪崩 / 防击穿 / 主动失效）贯穿商品、报表等读路径；推荐相似度采用「MySQL 表为真相来源 + Redis ZSET 热读缓存 + read-through 回填」范式，关机清缓存后首个请求自动重建。
5. **实时通信架构**：STOMP over WebSocket 实现会话认领制客服系统，含按归属路由、Redis 在线状态、超时自动释放、事务提交后推送消除 REST-then-WS 竞态、结构化 ERROR 帧，并配 WebSocket 端到端集成测试。
6. **鉴权设计**：路由放行与业务鉴权分离（过滤器只解析身份，角色/归属校验集中在 Service 层 `AuthUtil`，便于单测，也复用到无 `SecurityContext` 的 WebSocket / 定时任务 / 支付回调线程）；商品浏览类 GET 用单段通配符 `*` 精确放行避免误开受保护接口；JWT 无状态 + refreshToken 轮换 + **令牌版本即时撤销**（登出/改密旧 token 立即失效）。
7. **推荐算法**：item-based 协同过滤，加权余弦相似度（状态加权取最大），离线预计算 + 多级缓存 + 冷启动「同类目热销→全站热销」兜底，纯算法逻辑抽成纯函数独立测试。
8. **数据一致性细节**：下单两阶段（先全量只读校验、后统一写库）整链事务化、订单/地址快照防篡改、取消/退款自动恢复库存与多优惠券。
9. **统一响应与全局异常**：`Result<T>` + `@RestControllerAdvice` 一处收口，错误码语义化（含 401/403/400 细分），前端处理一致。
10. **健壮的测试体系**：**326 个测试**（41 测试类），以纯 Mockito 单测为主、辅以 WebSocket / 支付 / 语义搜索端到端集成测试（基础设施不可用时优雅跳过）；沉淀了 MyBatis Plus 3.5.9 的多处测试坑位与解法（见 [debug记录.md](./debug记录.md)）。
11. **文档驱动开发**：需求 / 接口 / 实现 / 决策 / 调试 / 前端对接 / 学习笔记多类文档齐全，技术决策均有「为什么」留痕（[重要决策说明.md](./重要决策说明.md) **63 条**），AI 子项目用 brainstorm→spec→plan→实现的流程沉淀设计过程。

## 十三、暂未实现与后续规划

`requirements.md §5` 的 8 项暂缓功能**全部完成**（第三方支付以**可插拔模拟网关**替代，预留平滑切换支付宝的抽象），并在此之上额外落地了**两个 AI 应用**。
**详细的分阶段任务与状态见 [下一阶段路线图.md](./下一阶段路线图.md)**：

- ✅ 阶段一：未支付订单自动取消（定时器）、并发安全（库存乐观锁 + 优惠券分布式锁）、热点读缓存
- ✅ 阶段二：报表导出 Excel、多优惠券叠加策略
- ✅ 阶段三：实时客服（WebSocket）、推荐算法（item-based CF）、模拟支付网关（替代支付宝沙箱）
- ✅ AI 方向：AI-1 语义搜索（outbox + Qdrant + 通义 embedding）、AI-2 RAG 导购问答（qwen + SSE）、AI-3 AI 导购 Agent（手写 Agent 循环 + 6 工具 + 生产化护栏）

**可改进 / 后续可优化项**：

| 方向        | 说明                                                                                                            |
| ----------- | --------------------------------------------------------------------------------------------------------------- |
| 真实第三方支付 | 当前为模拟网关，已留 `PaymentGateway` 抽象，可平滑替换为 `AlipayPaymentGateway`（创建支付→跳转→异步回调验签）|
| 推荐算法    | 相似度全量重建可改增量（C2 暂缓）；热销榜可预计算缓存                                                           |
| AI 加固     | embedding 文本仅用「商品名 + 类目名」（`product` 无描述字段），加描述后召回更准；RAG 当前单轮，可扩多轮会话      |
| 库存恢复    | （已改原子 `stock = stock + q`）—— 历史读-改-写窗口已消除                                                       |
| 缓存 Broker | WebSocket 用单机内存 SimpleBroker，多实例部署需换外部 Broker（RabbitMQ）+ Redis Pub/Sub 共享在线状态            |

> 已解决的历史技术债（库存超卖、优惠券超发、401/403 语义、非法请求体、`ApiResponse` 残留、`getCurrentUserId` 返回 null 等）见 [进度.md](./进度.md) 技术债表。
