# 南鲸商城 BlueWhale — 项目说明

> 一个专注国货品牌的在线购物平台后端，覆盖商品浏览、购物车、下单支付、库存管理、评论、优惠券与数据报表的全流程电商服务。
>
> 基于 Spring Boot 3 + MyBatis Plus + Spring Security(JWT) + Redis 构建，采用分层架构与无状态鉴权。除第三方支付外全部功能已完成，并扩展了**并发安全（乐观锁 + 分布式锁）、热点读缓存、报表 Excel 导出、多优惠券叠加、STOMP 实时客服、item-based 推荐算法**等进阶能力，配有 274 个测试（含集成测试）。

## 一、项目简介

南鲸商城（BlueWhale）是一个面向**消费者 / 门店店员 / 平台管理员**三类角色的多商店电商平台后端。它以 RESTful API 形式对外提供服务，前后端分离，前端可凭本仓库的 [前端对接文档](./frontend-handoff.md) 直接对接。

| 指标 | 数值 |
|---|---|
| 业务模块 | 12 个（用户 / 商店 / 分类 / 商品 / 购物车 / 订单 / 地址 / 评论 / 优惠券 / 报表 / 实时客服 / 推荐） |
| REST 接口 | 59 个（另有 2 个 STOMP 消息端点） |
| 数据表 | 16 张 |
| 主代码 Java 文件 | 171 个（含 18 Controller / 13 Service 接口 + 13 实现 / 16 Entity / 16 Mapper / 57 DTO，另有 job / listener / interceptor） |
| 测试 | 274 个（29 个测试类，纯 Mockito 单测 + WebSocket 端到端集成测试，全部通过） |

## 三、角色与权限

| 角色 | 标识 | 能力 |
|---|---|---|
| 游客 Guest | （未登录） | 浏览商店 / 商品 / 分类 / 评论 / 可领券列表 / 商品相关推荐 |
| 顾客 Customer | `CUSTOMER` | 购物车、下单、支付、确认收货、取消、退款、评论、领券用券、地址管理、个性化推荐、向店铺客服发消息 |
| 店员 Staff | `STAFF` | 管理**本店**商品 / 库存 / 订单（发货）/ 店铺优惠券，查看本店报表，接待本店客服会话 |
| 管理员 Admin | `ADMIN` | 创建/维护商店、发布全局优惠券、删除分类、查看全局报表、手动触发推荐重建 |

**鉴权策略**：无状态 JWT。登录签发 accessToken（24h）与 refreshToken（7d，存 Redis）。请求头 `Authorization: Bearer <token>`，由 `JwtAuthenticationFilter` 解析为 `AuthUser` 写入 `SecurityContext`；具体的角色与归属校验由 Service 层的 `AuthUtil` 完成（路由放行与业务鉴权分离）。

## 五、系统架构

经典分层 + 无状态安全过滤链：

```
                    HTTP 请求
                       │
            ┌──────────▼───────────┐
            │ JwtAuthenticationFilter│  解析 Bearer Token → AuthUser → SecurityContext
            └──────────┬───────────┘
                       │
            ┌──────────▼───────────┐
            │  SecurityFilterChain  │  /api/auth/** 与商品浏览类 GET 放行，其余需认证
            └──────────┬───────────┘
                       │
   Controller (@RestController)        路由、参数校验(@Valid)、统一包装 Result<T>
        │
   Service / ServiceImpl               业务逻辑 + AuthUtil 角色/归属鉴权 + @Transactional
        │
   Mapper (MyBatis Plus BaseMapper)    CRUD / 分页 / 逻辑删除；复杂聚合用自定义 SQL
        │
   MySQL  ＋  Redis(令牌 / 缓存 / 在线状态 / 分布式锁 / 推荐 ZSET)
```

**另有两条非 HTTP 路径**：
- **STOMP over WebSocket**（`/ws` 端点）：CONNECT 帧 JWT 鉴权（`StompAuthChannelInterceptor`）→ `@MessageMapping` 路由消息 → 内存 Broker 广播 / 点对点投递；在线状态由 `WebSocketPresenceListener` 维护到 Redis。
- **定时任务**（`@EnableScheduling`）：未支付订单自动取消（每分钟）、推荐相似度离线重建（每日 03:00）。

**横切设施**：
- `Result<T>` 统一响应封装（code/message/data）。
- `GlobalExceptionHandler`（`@RestControllerAdvice`）：校验异常→400、`BusinessException`→自定义码、其余→500。
- `MybatisPlusConfig` 分页拦截器；逻辑删除（`deleted` 字段）全局生效。
- `CacheUtil`/`RedisLockUtil`：热点读缓存（空值占位 + TTL 抖动 + SCAN 失效）与分布式锁（`SET NX EX` + Lua 解锁）。
- Flyway 数据库迁移：`V1~V5` 版本化迁移 + `R__` 种子，启动自动执行。

## 七、核心实现要点

> 详细算法与边界处理见 [实现说明.md](./实现说明.md)。

- **下单两阶段设计**：先只读全量校验（购物车归属、地址、库存、优惠券状态与过期、金额计算），全部通过后再统一写库（扣库存→建订单→建条目快照→核销券→清购物车），整体 `@Transactional` 保证原子性。
- **金额计算**：`DISCOUNT` 按折扣率、`AMOUNT_OFF` 按满减门槛，`payableAmount = max(0.01, total − discount)`，统一 2 位 HALF_UP。
- **分类树构建**：一次全量查询 + 两次线性遍历（Map 建索引 → 按 parentId 挂载），O(n) 组装嵌套树，避免递归查库。
- **避免 N+1**：列表场景统一「二次批量查询」（收集本页外键 → `selectBatchIds` 一次查 → Map 回填），如商品的 categoryName、评论的昵称。
- **快照机制**：订单条目与收货地址在下单时落库快照，商品改价/改名、用户改址均不影响历史订单展示。
- **Token 刷新与轮换**：`POST /api/auth/refresh` 校验 Redis 中 refreshToken 后签发新 accessToken，并**轮换 refreshToken**（旧值立即失效、重置 7 天），降低重放风险。
- **报表聚合**：`GROUP BY/SUM` 等 MyBatis Plus QueryWrapper 不支持的聚合改用自定义 SQL；门店与全局报表共用聚合逻辑，靠 `storeId IS NULL` 分支切换范围。
- **并发安全**：库存扣减用乐观锁（`@Version` + `stock >= q` 原子条件 + 重试 3 次）防超卖；优惠券领取用 Redis 分布式锁 + `remain_count > 0` 守卫防超发。
- **热点读缓存**：分类树 / 商店 / 商品详情 / 评论 / 报表等手写 `getOrLoad` 缓存（空值占位防穿透、TTL 抖动防雪崩），写操作主动 `SCAN` 失效。
- **多优惠券叠加**：券分 折扣 / 满减 / 直减 三类，同类至多一张、跨类叠加；后台穷举最优计价顺序，并提供下单前试算接口。
- **实时客服**：STOMP 消息按会话归属路由（未接入→广播店铺主题，已接入→点对点）；STOMP 推送延迟到事务提交后，消除 REST-then-WS 会话不可见竞态。
- **推荐算法**：加权余弦相似度（状态加权取最大），离线预计算写 `product_similarity` 表（真相来源）+ Redis ZSET 热读缓存（read-through），冷启动按「同类目热销→全站热销」兜底。

## 八、技术亮点

1. **路由放行与业务鉴权分离**：过滤器只负责解析身份，角色 / 店铺归属校验集中在 Service 层 `AuthUtil`（`requireRole` / `requireStoreAccess`），职责清晰、便于单测。这一思路也复用到非 HTTP 路径——WebSocket 与定时任务线程无 `SecurityContext`，故对显式传入的 `AuthUser` 校验、鉴权置于调用入口（如推荐重建的 Admin 校验放 Controller 层）。
2. **精确的安全放行**：商品浏览类 GET 用单段通配符 `*` 精确放行，避免误开同前缀下的受保护接口（如 `/api/stores/*/orders`、`/reports`）。
3. **无状态 + 刷新令牌轮换**：JWT 无状态鉴权配合 Redis refreshToken 轮换，兼顾水平扩展与安全；WebSocket 复用同一套 JWT，在 STOMP CONNECT 帧鉴权。
4. **并发安全实战**：针对真实的超卖 / 超发缺口，分别用**乐观锁**（库存）与 **Redis 分布式锁**（优惠券）封堵，并配重试与守卫条件，附迁移与决策留痕。
5. **多级缓存设计**：热点读缓存（防穿透 / 防雪崩 / 主动失效）贯穿商品、报表等读路径；推荐相似度采用「MySQL 表为真相来源 + Redis ZSET 热读缓存 + read-through 回填」的多级缓存范式，关机清缓存后首个请求自动重建。
6. **实时通信架构**：STOMP over WebSocket 实现会话认领制客服系统，含按归属路由、Redis 在线状态、事务提交后推送消除 REST-then-WS 竞态，并配 WebSocket 端到端集成测试。
7. **统一响应与全局异常**：`Result<T>` + `@RestControllerAdvice` 一处收口，错误码语义化，前端处理一致。
8. **健壮的测试体系**：274 个测试，以纯 Mockito 单测为主、辅以 WebSocket 集成测试；沉淀了 MyBatis Plus 3.5.9 的多处测试坑位与解法（见 [debug记录.md](./debug记录.md)），如 `BaseMapper` 重载消歧、`ServiceImpl.baseMapper` 反射注入、Lambda 缓存缺失等。
9. **文档驱动开发**：需求 / 接口 / 实现 / 决策 / 调试 / 前端对接 / 学习笔记多类文档齐全，技术决策均有「为什么」留痕（[重要决策说明.md](./重要决策说明.md) 52 条），并用 brainstorm→spec→plan→实现的流程沉淀设计过程。
10. **数据一致性细节**：下单整链事务化、快照防篡改、取消/退款自动恢复库存与优惠券（多券）。

## 九、快速开始

### 环境依赖

- JDK 17、Maven
- MySQL 8.x（默认 `localhost:3305`，库名 `bluewhale`，账号 `root/123456`）
- Redis 6.x+（默认 `localhost:6379`）

> 连接参数见 [application.yml](../src/main/resources/application.yml)，支持 `REDIS_HOST` / `JWT_SECRET` 等环境变量覆盖。

### 启动步骤

```bash
# 1. 初始化数据库（只需建空库，建表与种子由 Flyway 启动时自动迁移）
#    CREATE DATABASE bluewhale DEFAULT CHARSET utf8mb4;

# 2. 编译
mvn clean package -DskipTests

# 3. 运行
mvn spring-boot:run
```

启动成功后访问 `http://localhost:8080`。游客接口示例：`GET http://localhost:8080/api/products`。

> 测试账号创建（CUSTOMER 直接注册，STAFF 需 Admin 建店绑定，ADMIN 需 SQL 改角色）详见 [前端对接文档 §6.4](./frontend-handoff.md)。
